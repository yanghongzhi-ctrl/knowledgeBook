# 知识库一键发布流程

日期：2026-06-03

## 1. 目标

将知识库更新后的分散操作固化为可重复执行的发布链路：

```text
校验 → 质量检查 → processed 导出 → SQL 生成 → 本地 QA 评测
→ 本地资源评测 → embedding 重建 → PostgreSQL 导入
→ 数据库数量核对 → 数据库 keyword 评测 → pgvector 混合评测
→ 标记版本 released → 生成发布报告
```

发布失败时，命令返回非零退出码，并在报告中标明失败步骤。

## 2. 使用方式

### 2.1 本地发布检查

不重建向量、不修改数据库，适合内容编辑后的快速检查：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\release_chapter.ps1 -Chapter ch05
```

### 2.2 完整发布

重建向量、导入 PostgreSQL、执行数据库回归并标记版本为 `released`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\release_chapter.ps1 -Chapter ch05 -Full
```

首次初始化数据库时可增加迁移参数：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\release_chapter.ps1 -Chapter ch05 -Full -ApplyMigration
```

### 2.3 直接使用 CLI

```powershell
$env:PYTHONPATH='D:\knowledgebase\src'

py -m kb_rag.cli `
  --package 'data\raw\ch05\第5章_GIS理论基础与空间分析方法_知识库_v1.0完备版.json' `
  release `
  --generate-embeddings `
  --apply-db `
  --db-hybrid-limit 30
```

如果已有可复用的 embedding SQL，可省略 `--generate-embeddings`，发布流程会使用现有文件。

## 3. 发布门槛

默认发布门槛为 100%：

- 数据结构校验无错误；
- 本地 QA 评测通过率达到 100%；
- 本地资源评测通过率达到 100%；
- embedding 数量与 `Embedding_Corpus` 数量一致，维度为 1024；
- PostgreSQL 主要表数量与发布包一致；
- PostgreSQL 中非空向量数量与 `Embedding_Corpus` 数量一致；
- 数据库 keyword 评测通过率达到 100%；
- pgvector 混合检索抽样评测通过率达到 100%。

可通过 `--min-pass-rate` 调整门槛，但正式发布不建议降低。

## 4. 发布级校验

`validate` 当前额外检查：

- 资源、互动脚本、embedding 和资源评测题 ID 是否重复；
- `bound` 资源是否存在有效文件路径；
- 互动脚本是否引用存在的资源；
- embedding 是否有完整的 `source_type`、`source_id` 和 `embedding_text`；
- embedding 是否引用存在的答案卡、知识点或资源；
- 资源评测题是否引用存在的目标资源；
- 答案卡规范问题是否存在重复。

## 5. 数据库快照规则

同一 `version_id` 的种子 SQL 采用完整快照替换方式：

1. 删除该版本旧的评测运行和知识对象；
2. 重新插入当前发布包中的全部对象；
3. 再导入 embedding 更新 SQL；
4. 核对数据库数量和向量数量。

这样可以防止只执行 upsert 时，已经从知识包删除的旧对象继续残留在数据库中。

## 6. 发布报告

每章发布后生成：

```text
output/chXX_rag_engine/reports/release_report_chXX.md
output/chXX_rag_engine/reports/release_report_chXX.json
```

Markdown 报告适合人工查看，JSON 报告适合后续接入自动化平台或发布看板。
